# Aaltonomous Humanoid: feasibility for us (from the challenge page + starter repo docs, read 2026-11-13)
Facts (docs): policy server (websocket 8000, msgpack, 30 Hz) gets head/wrist RGB, head depth, arm_q(14), hand_q(14), instruction; returns absolute joint targets (14 arm + 14 hand, Dex3 = thumb 0-2, index 0-1, middle 0-1 per hand). Rules: 120 s, sim gate >= 27 Hz and 0 clipped steps, safety filter (arm <= 1.0 rad/s, hand <= 3.0 rad/s). Judging: real result 40, generality 25, originality 20, presentation 15. Top ~5 by SIM score run on the real G1 on Sunday; participants never touch the robot. Isaac sim needs RTX >= 24 GB, Ubuntu (Verda cloud; MSI 12 GB and Mac M2 cannot). `mock` backend runs anywhere (no images). Baseline (classical, CPU): 76-82 % rung 1 sim, no instruction parsing. Submission: Docker linux/amd64, <= 40 GB, must fit 32 GB VRAM, no network guaranteed.
Our assets do NOT transfer directly: glove data = human 5-finger hands, G1 is Dex3 3-finger + 7-DoF arms; real-robot teleop by participants is not offered in this track.
Cheap, plausible wins (estimates, unverified without the sim): (1) offline rule-based instruction parser (8 templates + paraphrases -> colour->bin map) feeding the classical planner for rung 2 (~2 h, testable on mock); (2) package/tune baseline Docker. Cost/risk: needs Verda access for any visual test; two tracks with 2 people and Tommaso's usage limit is the real constraint.
Rokoko track with G1 as embodiment: retarget glove -> Dex3 using INTERFACE joint names/limits (mirrored hands: left closes negative, right positive); thumb signal from our glove is unreliable (use SDK hand solver).
